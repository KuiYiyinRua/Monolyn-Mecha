# 闪现音效设置与供光报告复核

本地修改日期：2026-11-18。沿用模组版本 0.9.4，发布修订为 `2026-11-18-blink-sound`。

## 闪现设置

打开“选项 → 模组设置 → Monolyn: Mecha · 墨诺灵机甲”，勾选“关闭闪现音效”。默认不勾选，修改立即生效，并保存到原生模组配置。

设置覆盖追猎者手动闪现、本模组的自动闪现和前置在 1.7 中直接调用的自动闪现。仅在追猎者闪现执行期间将音频音量设为零；保留原生音效调用、两端视觉效果、位移和冷却。其他单位及其他用途的同名传送声音不受影响。该设置属于本地音频偏好。

两版共用 `Source/Settings.cs`。1.6 挂接原生 `Apply(LocalTargetInfo, LocalTargetInfo)`；1.7 额外挂接原生直接 `Blink(LocalTargetInfo)` 路径。作用域通过 finalizer 退出，异常不会把后续音效留在静音状态。

## 供光报告结论

报告没有提供日志、存档或模组列表。目前结论为 **在所测最小模组组合下未复现，未确认是本模组缺陷**。供光产品代码未因这份报告修改。

实测环境：RimWorld 1.7.5011 rev24，Core 与官方 DLC，Harmony、Humanoid Alien Races、Monolyn Race、本模组。另加载自动验证探针，不加载其他玩法模组。

- 在六类机体逐一生成前后，检查 BaptismalFont、BloodRegulator、DeepExtractor 的原生请求供光路径：建筑储光增加、光芒总池对应扣减。
- 不朽、巨像、掠夺者、禁断者使用真实储光接收器充能；追猎者、守护者及前置的 MNC_Distributor 保留原生机械族能量需求并正常充能。
- 持续运行至少 1500 个游戏 tick 后再次检查：光芒塔仍存在并连通，三种建筑保持连线且能继续接收光芒。
- 音效开关前后均完成真实闪现，保留同一个 Pawn、到达目标位置并执行两端原生特效；开启静音后声音调用的音量为零，关闭后恢复，共享音效在闪现之外仍正常。
- 原生设置窗口已截图检查。设置写入与重启读取分别验证，避免在运行中的世界中重新进入全局 Scribe 加载器。

未覆盖：用户原存档、其他模组组合、所有建筑类型、整段配方制作耗时、1.6 引擎实机及多人双端。不能把“本次未复现”解释为所有环境都不可能发生。

本机前置与游戏基线仍有 AncientHeavyBridge 缺失、Monolyn 神祇命名规则等现有日志；没有把这些错误视为本模组供光故障。

## 验证入口与证据

探针：`Tests/LightAndBlink/Probe.csproj`。按工程参数传入 1.7 游戏、ASEL、Harmony 和候选核心 DLL；将探针 DLL 放入隔离 `Tests/RimWorld17` 验证包的 Probe/Assemblies，使用 `-quicktest -mm-light-blink` 启动。供光检查在设置读取操作前执行；新探针仅读取设置 XML，重启持久化使用 `-mm-blink-settings-cold` 单独检查。

证据目录：`BuildValidation/LightAndBlink-20261117/`。`Full-R6` 保存完整运行断言、1500 tick 状态快照、加载清单和设置窗口截图；最终 `validation-report.json` 记录构建与部署散列。前几轮失败记录保留，用于区分测试夹具问题和产品行为。临时游戏与测试构建缓存在验收结束后清理。
