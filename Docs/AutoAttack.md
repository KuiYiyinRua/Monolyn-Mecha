# 自动攻击回归：0.9.1

四种可驾驶战甲在加入无人驾驶组件后，即使驾驶员已经登机，原版 `GenHostility.HostileTo(Thing, Thing)` 仍会把它们视为未受机械师控制的机械体，直接返回非敌对。自动选敌因此得到空列表。手动指定目标绕过自动搜索，因此不朽、巨像和掠夺者仍能手动开火；禁断者的武器校验也使用敌对判断，受同一原因影响。

修复仅替换这个敌对判断中的两处机械师条件。驾驶员在舱内或未绑定机械师的战甲按正常阵营关系判断；已绑定的空舱战甲继续接受原版控制/带宽判断。其余敌对条件、机械师组件初始化、机械体控制组、驾驶条件、武器参数及随机状态保持原逻辑。原版方法形状改变时会明确报错，避免静默漏补丁。

功能回归还发现 `MechaCombatAI.SetEnabled(false)` 只在当前Job恰为自动战斗时清除武器目标。禁断者可能在Wait中保持已启动球体，导致关闭自动战斗后旧目标仍被继续使用。最终版本关闭自动战斗时始终清除目标，保留已放出球体的自然持续时间。手动攻击随后设置自己的新目标，因此不受此清理影响。

## 回归测试

`Tests/AutoAttack` 使用真实 RimWorld 主机和客机。客机触发实际自动开火、自动战斗、离机、登机按钮和登机菜单；测试不会直接指定敌人或启动自动战斗任务。

- 四种有驾驶员战甲、四种已绑定战甲、追猎者和守护者，共十个单位。
- 三轮自由射击、关闭自由射击后的独立自动战斗、关闭并离机、重新登机并开启的场景。
- 检查实际命中、自然生成的战斗任务、双向敌对与原版目标缓存、友方排除、原生关系组件、25点总带宽、关闭后的停止射击。
- 对比双端每阶段断言、最终世界/地图时钟和随机状态；核验运行期间文件哈希未改变。

本轮证据保存在 `BuildValidation/AutoAttack-20261018`。`MP-Baseline-R1` 的测试靶因旧种子未包含 Pirate 本体派系而无阵营，此轮不能作为产品故障证据；`MP-Baseline-R2` 选择实际敌对的 PirateYttakin，并先验证其与殖民者敌对。R2 中四种有人驾驶战甲均零发射、零候选目标；四种无人驾驶战甲和两种构装体均有实际命中，双端一致。

`MP-Smoke-R1` 已恢复十个单位的命中，但错误地要求禁断者在单个检查时刻必须处于战斗Job；其放球锁定期间可以在Wait中继续正常输出。因此最终用例关闭自由射击，单独验证自动战斗阶段自然生成过战斗Job且产生命中，再检查两开关同时开启，避免以瞬时Job名误报。

`MP-Smoke-R2` 的独立自动战斗阶段通过；关闭阶段复现了禁断者残留目标问题，双端开关均为关闭但仍有30次命中。该轮不能作为最终通过记录，最终候选为 `Candidate-R2`。

按用户本次要求只做功能确认，不进行120000 tick长测。候选版本及最终验证结果见同目录的运行记录。测试使用独立游戏目录、独立存档和本机专用端口，不覆盖玩家存档；`Tests/AutoAttack` 只在显式测试参数下启用。整合包全部其他模组、跨电脑、异步时间和多派系未在本轮覆盖。

最终 `MP-Functional-Final` 通过三轮共12个双端阶段，运行19260个共同tick，双方断言、最终地图/世界时钟及随机状态一致，未发生失步。已将 `Candidate-R2` 的308个运行文件逐一与本地安装核对一致；两个正式DLL版本均为0.9.1.0，所有测试进程均已退出。0.9.1发布沿用这套经过验证的DLL，安装包排除两个调试符号文件。

## 运行方式

先使用目标游戏的 `GameRoot` 和候选核心 DLL 的 `MechaAssembly` 构建 `Tests/AutoAttack/MultiplayerProbe.csproj`。然后调用 `Tests/AutoAttack/RunMP.ps1`，提供新的 `RunRoot`、候选模组目录 `Mecha`、`GameRoot` 和可选 `SeedSave`；`Ticks` 默认12000，长测使用120000。窗口控制复用 `Tests/SelfDestruct/Run.ps1` 的辅助类型。测试组件保留旧种子的类型名以兼容其序列化。

安装后需要退出并重启游戏；Multiplayer全员必须使用相同完整版本。
