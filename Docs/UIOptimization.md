# 0.6.3 界面性能优化与联机验证

状态：已本地部署。部署时间（UTC）：2026-10-14T14:28:52.503471+00:00。核心及可选联机适配与通过最终测试的 CandidateR4 完全一致，构建均为零警告、零错误。按用户要求停止追加性能测试，不给出最终精确降幅。

## 四处热点的改动

- `Pawn_Immortal.GetGizmos`：保留完整原生枚举；每台机甲复用自己的状态条与自定义命令，避免重复创建按钮和回调。
- `MechaActions.Gizmos`：返回每台机甲独立的按钮数组，登乘／下机按驾驶员切换。每次查询重新判定供电、驾驶员、移动锁定、迁移冷却和网络状态，并清除过期禁用标记。点击时读取当前地图，仍进入原有同步执行入口。
- `Pawn_Immortal.GetInspectString`：检查面板与状态条共用当帧的载重、结构、光芒和文本。原生检查文本仅在同一 GUI 帧、tick、地图和语言内复用；下一帧重新读取，GUI 外仍调用原生方法。
- `Gizmo_ImmortalStatus.GizmoOnGUI`：复用未变化数值的格式化文本，只在 Repaint 绘制纯显示状态条；本机原生 TooltipHandler 同样在 Repaint 注册悬停提示。

缓存不写入存档，也不参与模拟或随机数计算。暂停时仍按画面帧刷新，最多一帧显示延迟。语言对象或 Def 变化时重建相关缓存。动作执行器、搬运 JobDriver 和联机适配逻辑未改；搬运容量继续读取实时 InventoryMass。加入点重载后的新 Pawn 创建自己的命令，不沿用旧对象的回调。

`MMUIB04/MMUIC05` 使用同存档、同数值和依赖，各完成 6000 tick 的真实 GUI 采样，四个目标均有非空记录，观察到耗时降低。但活动场景中出现了不同伤势和镜头状态，不能把观测值当作严格控制后的最终降幅，也不能据此推算整局 TPS 或 FPS。
